本文件汇总本轮「平衡 / 打磨候选版」的全部改动、证据与未完成项。
数据来源：`scripts/simulate-balance.mjs`（12 确定性种子，战役 1080 场 + 沙盒 288 场），
明细见同目录 `balance-baseline.md` / `balance-baseline.json`。

## 0. 本轮新增的可复现基础设施

| 文件 | 作用 |
| --- | --- |
| `scripts/balance-harness.mjs` | 无头运行层：按 `index.html` 的真实加载顺序把 **生产代码原封加载** 进 `node:vm`，只替换 DOM / 表现层 / 定时器，提供确定性种子（`__setHarnessSeed`）、虚拟时钟、无 DOM 适配。**不复制任何战斗数学。** |
| `scripts/balance-sim.mjs` | 战斗驱动与指标采集：在最外层包裹真实 `playCard` / `draw` / `applyStatus` / `beginTurn` / `applyCard` / `checkGameOver`，只读记账，不改结算。 |
| `scripts/simulate-balance.mjs` | 本地大矩阵 CLI（默认 12 种子；`--quick` 4 种子；`--seeds=N`），产出 `docs/balance/` 下的机读与人读报告。 |
| `scripts/verify-balance-guardrails.mjs` | CI 小矩阵护栏（默认 3 种子），已注册进 `verify-all.mjs`。 |

设计要点：

- **单一数学来源**：模拟器调用 `js/fixed-card-library.js`、`js/fixed-game-rules.js`、`js/campaign-*.js` 的同一套生成 / 结算 / AI / 能量 / 回合过渡；只有「无 DOM 适配」是新增代码。
- **确定性**：`character/enemy/stage/difficulty/seed` 相同 → 结果逐字段一致（护栏里有专门断言）。模拟器**不**改真实游戏的玩家侧随机性。
- **虚拟时钟**：真实代码里所有 `setTimeout` 被替换为按时间排序的队列，保留真实的**延迟顺序**但不等真实墙钟；12 种子全矩阵约 4 秒。

### 1.1 总体（12 种子）

| 指标 | 战役模式 | 沙盒模式 |
| --- | --- | --- |
| 场次 | 1080 | 288 |
| 胜率 | 47.1% | 50.0% |

### 1.2 核心发现：全部主要异常同源于「固定敌方等级 × 指数等级曲线」

`levelHp(level)` 在 1–100 级之间跨越约 10 个数量级，而战役的敌方等级是**写死的**
（第 1–5 关依次为敌方角色 53 / 59 / 69 / 94 / 100 级），六名可玩角色却是 61–93 级。
于是同一关对高等级角色是「秒杀」，对低等级角色是「必败」。`第 3.1 节` 矩阵：

| 角色 | 角色等级 | 第1关 | 第2关 | 第3关 | 第4关 | 第5关 |
| --- | --- | --- | --- | --- | --- | --- |
| 丽莎娅 | 67 | 100.0% | 100.0% | 0.0% | 0.0% | 0.0% |
| 罗林福 | 61 | 100.0% | 16.7%(僵83.3%) | 0.0% | 0.0% | 0.0% |
| 艾露希娅·卡佩恩 | 86 | 100.0% | 100.0% | 100.0% | 0.0% | 0.0% |
| 摩罗哥·恩典 | 62 | 100.0% | 16.7%(僵83.3%) | 0.0% | 0.0% | 0.0% |
| 赫卡莫斯·烬 | 93 | 100.0% | 100.0% | 100.0% | 0.0% | 33.3% |
| 苏 | 93 | 100.0% | 100.0% | 100.0% | 0.0% | 0.0%(僵91.7%) |

派生出的四类异常：

1. **推进墙**：第 4 关对全部六名角色、三档难度均为 **0.0%**（玩家在 5.9–7.3 回合内被清空）。
2. **碾压 / 无玩法**：艾露希娅（86 级）在第 1–3 关平均 **2.48 回合**、剩余生命 60% 结束，等于没有对抗过程。
3. **僵局**（真实游戏**没有回合上限**，所以这是"打不完"而不是"模拟器截断"）：整体僵局率 7.8%，
   集中在等级接近的对局——罗林福(61)/摩罗哥(62) 对第 2 关(59 级) 僵局率 **83.3%**，苏(93) 对第 5 关 **91.7%**。
   实测机制：等级接近时双方每回合伤害约为自身生命上限的 1.8%，而治疗 / 护盾的续航量级相当，
   于是谁都打不死谁（例：罗林福 vs 第 2 关，13 回合后玩家仍剩 93.4% 生命）。
4. **等级门槛导致 8 费高级卡永远打不出**：`maxHighCost` 规定 70 级才解锁 8 费。
   艾露希娅（86 级）的 `大地君王Ⅲ`（8 费）在 1080 场里抽到 45 次、打出 **0** 次——
   不是因为估值问题（护栏杆件已证明"可支付却不出牌"= 0），而是她的对局平均 2.48 回合结束，**根本到不了 8 费**。

### 1.3 能量曲线 / 费用倍率（结论）

- 能量曲线本身**正确**：`roundEnergy` 第 1–4 回合为 3/5/7/9，第 5 回合起封顶 10；8/9/10 费卡理论首次可用回合 = 4/4/5。
- 高费卡**并不被埋没**：实测首次打出回合 cost8 = 9.62、cost9 = 7.79、cost10 = 9.07；抽到后打出率 66.7% / 68.8% / 62.5%。
- 每费收益随费用上升（cost1 ≈ 5.68M → cost10 ≈ 42.8M），**未出现高费倒挂**。
  `COST_MULTIPLIER` 各档倍率严格递增（护栏已把这条写成硬断言）。
- 低费档的「每费收益」偏低（cost4 = 2.41M、cost5 = 1.68M）是**统计口径**造成：
  该指标只统计 `damage` 量，而这几个费用档里治疗 / 护盾 / 状态牌占比高，其 `amount` 天然为 0 或很小。
  按卡牌类型拆分统计仍待补充（见 §5 未完成项）。

## 2. Change Report（逐项改动：旧值 / 新值 / 证据 / 影响）

> 本轮**没有**改动任何战斗数值公式、倍率表、能量规则、难度系数或 `STAGE5_BOSS_TUNING`。
> 所有改动都是「修复失效机制 / 统一决策来源 / 修正模拟保真度 / 修正时间轴缩放」。

### 改动 1 — 元素克制统计与卡面提示完全失效（缺陷修复）

| 项 | 内容 |
| --- | --- |
| 旧值 | 元素克制触发均值 **0.00**（1080 场全部为 0）；卡面「克制 +20%」徽标从不出现 |
| 新值 | **0.35**（战役）/ **0.38**（沙盒） |
| 证据 | 固定卡库用 `effectType: "damage"`，而 `index.html` 的 `DIRECT_DAMAGE_EFFECT_TYPES` 只列了旧内联生成器的 `attack/burn/freeze/curse/execute/lifesteal/pierce`。因此 `isDirectDamageCard()` 对**所有固定卡恒为 false**，`cardAdvantageTarget()` 恒返回 `""`。 |
| 改动 | `index.html` 的 `DIRECT_DAMAGE_EFFECT_TYPES` 加入 `"damage"`（两套命名并存）。 |
| 影响 | **只影响统计与 UI**（克制徽标、威力标签、机制描述）。伤害倍率本来就生效——`js/fixed-game-rules.js:152` 的 `resolveDamage` 直接用 `elementMultiplier(element, target)` 按属性字符串结算，与 `effectType` 无关。因此本改动**没有**改变任何伤害数值。 |

### 改动 2 — AI 效果估值尺度不一致 + 缺少资源意识（核心）

| 项 | 内容 |
| --- | --- |
| 旧值 | 非伤害效果使用**固定点数**：状态 1200 / 抽牌 800 / 能量 400 / 净化 300 / 召唤 100；Persona 倍率 ×5–×12 |
| 新值 | 一律以 `actor.maxHp` 为锚点（与伤害/治疗/护盾同量纲，随等级自动缩放）；Persona 倍率收敛到 ×1.5–×3.2；新增 `planAiPlay()` 1–2 张浅层组合前瞻（`AI_LOOKAHEAD_WIDTH = 5`，无搜索树 / 无 Minimax） |
| 证据 | 等级缩放落地后伤害量级是 10^5–10^9。固定点数 1200 相对 10^8 的比值约 1.2×10⁻⁵ —— 数学上等同 0，所以「状态 / 抽牌 / 能量 / 净化 / 召唤」这五类效果此前对 AI 毫无价值。 |
| 改动文件 | `js/campaign-mode.js`（估值 + 前瞻 + 单一上下文）、`js/fixed-game-rules.js`（沙盒 AI 改为调用同一个 `aiChoosePlay`）、`js/campaign-runtime.js`、`js/campaign-rules.js`、`js/campaign-ui.js`（全部收敛到 `aiChoosePlay` / `aiContextFor` / `intentTypeForCard` 三个唯一入口） |
| 影响 | 决策面见 §3 AI Report。**整体结果指标无实质回退**：胜率 48.0% → 47.1%（在种子噪声内）、平均伤害 355.4M → 356.1M、能量浪费率 19.1% → 19.0%。 |

### 改动 3 — `verify-campaign.mjs` 契约断言重定向

| 项 | 内容 |
| --- | --- |
| 旧值 | `assert.match(campaignRuntimeSource, /actor: state\.enemy, target: state\.player/)` |
| 新值 | 断言 runtime 必须走 `mode.aiChoosePlay(state, "enemy")`，且**不得**再内联复制 `actor/target` 上下文；同时断言 `aiContextFor(state, side)` 存在于 `campaign-mode.js` |
| 证据 | 该断言原本保护「AI 重新规划必须携带态势上下文」。改动 2 把这个内联上下文换成了唯一构造点 `aiContextFor`，旧断言的实现细节随之失效。**保护意图保留、并按代码新形态重写**（没有削弱、没有删除）。 |

### 改动 4 — 修复 `originalChooseCard` 悬空引用（潜在崩溃）

`js/fixed-game-rules.js` 里 `aiController.chooseCard` 的保底分支引用了 `originalChooseCard`，
但改动 2 把它的 `const` 声明删掉了——一旦走到该分支就会抛 `ReferenceError`。
已补回 `const originalChooseCard = aiController.chooseCard.bind(aiController);`。

### 改动 5 — 敌方回合等待未随战斗速度缩放（节奏缺陷）

| 项 | 内容 |
| --- | --- |
| 旧值 | `aiController.takeTurn` 里 3 处等待是**硬编码、不随速度缩放**的：`850`、`650 + rng()*450`、`650` |
| 新值 | 改为 `scaledDramaMs(…)`，与特效锁 / 命中揭示 / 输入恢复共用同一条缩放时间轴 |
| 证据 | `battleSpeedDelay` 已按档位缩放（normal 1 / fast 0.55 / ultra 0.3），但 AI 回合的主要等待绕过了它：**「极快」档位下 AI 回合几乎不变快**。见 §4 Pacing Report 的量化。 |
| 影响 | normal 档位**完全不变**（因子 1），只让 fast / ultra 真正生效。 |

### 改动 6 — 模拟器保真度（仅影响测试，不影响游戏）

- 修正「共鸣后不重新决策」：激活回响 / 星耀会改变能量与费用，旧驱动仍用共鸣前的决策 →
  造成「刚补了资源却不打牌」的**假缺陷**。现改为共鸣后重新决策一次（与真人行为一致）。
- 单回合出牌步数上限 12 → 32：真实规则只受能量与手牌约束，低费牌 + 抽牌一回合可以打出十几张，
  12 步会**人为截断伤害**并污染基线。
- 新增结构完整性采样（NaN / 负能量 / HP 越界）、驱动循环耗尽检测、以及
  「有能量且有可支付牌却结束回合」的结构信号（应为 0）。

## 3. AI Report（行为差异）

同一批真实对局状态（6 角色 × 5 关卡 × 种子 1000），把**旧版 `aiCardScore`**（从 `git HEAD` 只读取出）
与新 `aiChoosePlay` 放在**同一状态**上对比选牌：

```
决策样本 394；选择不同 153；差异率 38.8%
  47  old:伤害 → new:基础牌
  20  old:基础牌 → new:基础牌（不同张）
  14  old:伤害 → new:伤害（不同张）
  14  old:伤害 → new:护盾
  11  old:基础牌 → new:伤害
   9  old:治疗 → new:基础牌
   9  old:治疗 → new:伤害
   7  old:基础牌 → new:治疗
   7  old:基础牌 → new:护盾
```

解读：

- 由于对比时 `style: null`，Persona 倍率不参与，因此**差异全部来自估值模型本身**。
- 最大一类（47 次）是「旧 AI 打一张昂贵伤害牌 → 新 AI 改打基础牌」：新模型按**每费收益**排序并做 1–2 张组合前瞻，
  这正是本轮要求的「不要只看当前最高分那一张，要考虑剩余能量还能不能继续出牌」。
- 同时新 AI 更愿意为「护盾 / 治疗」腾出能量（伤害→护盾 14 次、基础牌→护盾 7 次），
  对应「低血时防御价值上升」的规则。

**必须说明**：这 38.8% 只是**行为差异**，不是"更好的证明"。综合结果指标（胜率 / 伤害 / 能量浪费）
在种子噪声内没有变化，因此"新决策是否更优"需要**真人试玩**判定——这也符合本仓库对平衡改动的一贯标准。

## 5. 未完成 / 需要你决策的部分（诚实清单）

### 5.1 需要你批准的**设计级**改动（本轮**只量化、未改**）

按指令要求「如果确实存在 mismatch，不要急着改，先量化影响」，以下是量化结论与建议，**我没有动**：

- **建议**：让敌方 Runtime Level 相对玩家等级取偏移（例如 `clamp(playerLevel + offset, …)`），
  使关卡成为真正的难度坡道，而不是"等级门槛"。
- **为什么没做**：
  1. 第 5 关的 `STAGE5_BOSS_TUNING = { hp:.07, damage:.09, defense:.004, heal:.01 }` 是**针对 lv100 绝对量级标定**的。
     一旦把 Boss 等级改成随玩家浮动，`0.07` 这个系数就必须重新标定，否则第 5 关会反向失守（过低等级玩家变得过于轻松）。
     而重新标定第 5 关需要「模拟 + 真人游玩」双重证据，本轮只有前者。
  2. 这属于改变战役难度**身份**的设计决策（是"等级门槛制"还是"等级匹配制"），不是单点数值微调。
  3. 早前的试验（把敌方等级按玩家等级 + 偏移重算）**证实**了上述风险：第 5 关胜率一度升到 91–99%，
     因为 lv100→lv98 就删掉了 0.07 的压缩与 22.8× 的 `levelHp` 台阶。
- **可选的保守替代**（若你想走最小改动路线）：只给第 1–3 关加**相对等级上限**（例如 `enemyLevel = min(enemyLevel, playerLevel + 3)`），
  不动第 4、5 关。这能消除"高等级角色 1.5 回合秒杀前 3 关"，但**不能**解决低等级角色（61–67）无法推进第 3–5 关的问题。

### 5.2 需要你批准的**僵局**处理

真实游戏没有回合上限，"双方都打不死对方"会一直持续下去（实测僵局率 7.8%）。
两条互斥路线，请择一：

- **A（数值）**：提高伤害吞吐或降低续航（治疗 / 护盾），让对局在合理回合内收敛。**影响面大**：
  全局 `BASE_SCALE` / `levelHp` 锚点 / 治疗护盾 ratio，会同时影响全部 30 名角色与已被保护的第 5 关。
- **B（规则）**：给战役加"回合上限 + 判定"（例如 N 回合后按剩余生命百分比判定）。这是**新玩法规则**，需要你确认是否接受。
