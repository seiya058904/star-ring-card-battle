## 🏰 Five Encounters. One Journey.

The first campaign route follows five authored confrontations, from an opening shadow trial to a final dragon-god battle. Enemy tactics, stage transitions, and victory grades give each encounter its own purpose.

<p align="center"><code>SHADOW TRIAL → FROZEN ARROWS → FIRE FRONT → DRAGON KING → ANCESTRAL DRAGON</code></p>

Winning unlocks the next stage for that character. The game also records recent campaign results and their grades. Campaign progress is stored in the browser, not in a cloud account.

## 🎨 A Stage of Metal, Magic & Motion

The battle presentation combines pixel-fantasy artwork with engraved card frames, dark metal, warm gold, character portraits, and element-specific attack effects. The central card reveal, damage feedback, character actions, and result presentation are designed to make each play feel consequential while leaving the HUD, hand, and log readable.

- **Distinct card treatments:** base, normal, advanced, and special cards retain recognizable materials and cost information.
- **Elemental impact:** fire sparks, ice shards, wind arcs, heavy earth strikes, and broken lightning trails give different attacks distinct motion.
- **Readable across screens:** desktop, narrow, and short-screen layouts preserve real card hit areas and essential controls.
- **Motion preferences:** playback settings and `prefers-reduced-motion` adjust presentation without removing the information needed to play.

### 💻 Run the Web Source Locally

From the repository root, start a simple static server:

```powershell
python -m http.server 8000
```

Open **http://127.0.0.1:8000/**. The Web game uses plain HTML, CSS, and JavaScript. There is **no npm build step** for the browser application.

> [!NOTE]
> **Progress is local to the browser.** Campaign records use `localStorage`, so clearing site data or changing browsers/origins can make that progress unavailable. The Web and Android editions share game resources, not an automatic cloud-save service.

## ⚙️ For Developers

The root Web files are authoritative. The Android `app/src/main/assets/www/` directory is a **generated offline mirror**, not a separate place to hand-edit game logic.

### Web checks

```powershell
node scripts/verify-all.mjs
```

This runs the repository's consolidated regression checks for combat, campaign behavior, presentation boundaries, storage, and Web/Android asset parity. Browser input and responsive behavior should also be checked in a real browser when those areas change.

### Android asset synchronization and Debug build

For authorized changes to authoritative Web assets:

```powershell
node scripts/sync-android-web-assets.mjs
node scripts/verify-android-web-assets.mjs
```

A separate Android build requires **JDK 17** and the configured Android SDK:

```powershell
.\android\gradlew.bat -p android assembleDebug --no-daemon
```

The Android configuration currently uses `versionName 1.2.8` and `versionCode 13`. Do not change signing, republish historical tags, or substitute a newly generated APK for the existing GitHub Release without an explicit release task.

See [`AGENTS.md`](AGENTS.md) for source ownership, validation requirements, and maintenance restrictions, and [`DESIGN.md`](DESIGN.md) for the established presentation system.
